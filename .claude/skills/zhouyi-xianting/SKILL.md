# 周易仙庭 · 起卦 → 解卦 → 提示词

## Overview

一条链路:**输入条件 → 起卦(展示演算)→ 解卦(引经文)→ 现场撰写提示词**。

本 skill 自包含:全部数据在本目录 `references/` 下,不依赖任何外部脚本或仓库。提示词由 agent 按规则现场撰写——一致性与质量靠**固定译名、固定模板、锚点词表与自检清单**约束(见 `references/dialects.md`),不是靠预生成。

核心原则:画面结构就是卦的结构本身,不是给卦义配插图;时间结构就是爻的结构。

## 起卦:条件 → 卦象

用户没直给卦时,先起卦。**演算必须逐步展示、可复核**——数字摆在明处,读者能验算。

### 先天八卦数与爻位

乾1 兌2 離3 震4 巽5 坎6 艮7 坤8(余 0 取 8)。爻位自下而上:初1 … 上6(余 0 取 6)。

### 模式 A:日期/时间卦(默认,「今天/8月17号/现在」)

1. **年支序** = (公元年 − 4) mod 12 + 1 → 地支序(子1 丑2 寅3 卯4 辰5 巳6 午7 未8 申9 酉10 戌11 亥12)。如 2026 → (2026−4) mod 12 + 1 = 7 = 午。
2. **月数** = 公历月(1–12),**日数** = 公历日(1–31)。
3. **时支序** = 提问时刻所在时辰:23:00–01:00 子(1),1–3 丑(2),3–5 寅(3),5–7 卯(4),7–9 辰(5),9–11 巳(6),11–13 午(7),13–15 未(8),15–17 申(9),17–19 酉(10),19–21 戌(11),21–23 亥(12)。用户未给时间 → 用当前时刻,并在演算中注明「以提问时刻 X 时(支X)入算」。
4. **上卦数** = (年+月+日) mod 8;**下卦数** = (年+月+日+时) mod 8;**动爻** = (年+月+日+时) mod 6。

传统梅花易数用农历;本 skill 采用**公历变体**以保证 agent 可复算、结果可复核,输出时注明一句。用户明确给农历日期,则各数直接按农历取。

### 模式 B:数字卦

两个数 a、b:上 = a mod 8(0→8),下 = b mod 8(0→8),动爻 = (a+b+时支序) mod 6(0→6)。单个数字:按十进制位拆前半/后半两数(奇数位则前半多一位),再按两数处理。

### 模式 C:字数卦(用户给一句话/一个问题)

去标点后总字数 n:前半 ⌈n/2⌉ 字定上卦(字数 mod 8,0→8),后半定下卦,动爻 = (n + 时支序) mod 6(0→6)。

### 模式 D:直给卦

用户直接给卦名/卦序 → 查表即得。动爻可选:未指定则省略动爻环节,解卦只引卦辞与大象,视频不标强调幕。

### 定卦自检(必做)

1. **查表**:在 `references/hexagrams.json` 中找 `upper`/`lower` 与起卦结果匹配的那条,得卦名、卦序、卦画 `lines`。
2. **卦画核对**:卦画 = 下卦三位 + 上卦三位(自下而上,1 阳 0 阴;乾111 兌110 離101 震100 巽011 坎010 艮001 坤000)。自算的卦画与表内 `lines` 不符 → 演算有错,回头查,不得带错往下走。
3. **之卦**:有动爻时,把卦画自下而上第 k 位翻转(0↔1),再查表得之卦名,留作解卦。

## 解卦

素材全部来自 `references/hexagrams.json`,原文照引,不改字:

- **卦辞**(guaci)与**大象传**(daxiang)必引;
- 有动爻:引该爻爻辞(yaoci 第 k 条的 text);
- 之卦卦辞引一句,点「势之所趋」;
- 配 2–3 句白话,贴合用户所问(未问具体事则作「今日之象」)。

措辞克制:只作文化意象与自我观照,不给医疗、投资、法律类断言,不故弄玄虚。

## 转译:卦 → 画面

规则**精确定义、不许即兴**:旋钮取值、灵禽、色板一律照抄 `hexagrams.json` 该卦条目,理由字段(`*_reason`)随行,不自创取值。

1. **八境**:乾→天阙、坤→地宫、震→雷坛、巽→风廊、坎→水府、離→火殿、艮→山门、兌→泽苑。八境共处同一座仙庭山水,气候连续。
2. **叠合规则(支点)**:上卦占画面上方,下卦占画面下方,64 卦一律遵守。八纯卦为单境双重叠加、层层推向极致。这条规则自动画出「交与不交」:泰(坤上乾下)地宫悬于天上、天阙反在脚下;否(乾上坤下)天阙高悬、一层死云隔断两境。**下卦画到了上方 = 卦义反了,重来。**
3. **三旋钮**:光时(拂晓/正午/薄暮/夜)、天候、水势,表达卦义;`hexagrams.json` 已有全部 64 卦的取值与依据。
4. **远景人物**:画面里**唯一**的人物元素 —— 古风女子的背影,照抄该卦 `figure`(人数/姿态),衣色取该卦色板的点缀色。远景小点、不露脸、不写容貌年龄。人数与姿态编码卦义(1 孤 / 2 合 / 3 群),不自创。不画近景人物与人脸。
5. **色板**:照抄该卦 `palette_zh` / `palette_en`——上境签名色 + 下境签名色 + 光时点缀色,**两主一辅,三色上限**。
6. **宏大锚点**:整体明亮通透、空气发光、暗部不压死黑;建筑悬空;巨瀑入云;远景人物作尺度锤;地平线附近第二座极小同名境;前景受光精细浮雕;**天空云海约占三分之二,留白即宏大,切勿填满**;顶部约五分之一留白供后期排字,图上不渲染文字。中英对照全文见 `realms.json` 的 `global_anchors`。

## 输出契约

按序输出三段:

1. **起卦** — 方法名、逐步演算(含时辰说明)、本卦(卦序/名/卦画/上下卦)、动爻、之卦。直给卦则只列卦信息。
2. **解卦** — 经文引用 + 白话(见上节)。
3. **提示词** — 每条一行模型标题 + 一个只含提示词的代码块,按 `references/dialects.md` 的模板撰写,交付前过一遍模板末尾的**自检清单**。
4. **抖音发布文案** — 标题行 + 简介 + 6 个话题,按实际粘贴顺序给在一个代码块里;另附一行封面排字建议。模板见 `dialects.md` 第 3.5 节,素材见 `douyin.json`。用户说「不要文案」时省略此段。

默认产出:静态四模型(Midjourney 8.2 / GPT-Image-2 / Nano Banana Pro / Seedream 5.0 Pro)、3:4 竖版。可选参数(用户可指定):画幅 16:9;模型子集;视频(Seedance 2.5 一镜到底或六镜头分镜 / MiniMax H3 同两结构)。视频六幕取 `video.json` 该卦 `beats`,每幕动作照抄,`reason` 引用的爻辞可在解卦段呼应;**动爻对应的那一幕标注「动爻强调」,运镜幅度加重一级并注明**。多条提示词必须同源:主体、光源方向、色板、画幅一致。

## Red flags

| 症状 | 说明 |
|---|---|
| 演算没展示 / 数字一步带过 | 起卦不可复核,重写演算过程 |
| 公历农历混用且未注明 | 本 skill 默认公历变体,给了农历要写明 |
| 自算卦画与 `lines` 不符 | 演算有错,回头查,不得继续 |
| 下卦画到画面上方 | 叠合规则破了,卦义反了 |
| 天阙译成 Heavenly Palace 之类 | 译名漂移,照抄 `realm_en` |
| 旋钮取值与数据不符 / 自创理由 | 一律照抄 `hexagrams.json` |
| 色板超三色 | 模型会调出浑浊的灰 |
| 画面里同时出现灵禽与人影 | 人物只此一处,照抄 `figure` |
| 写了女子的容貌、年龄、五官 | 只写衣制、姿态、朝向 |
| 抖音文案出现「转发好运/测测你的/必看」 | 诱导表述,见 `douyin.json` 的 `banned` |
| 出现近景人物/人脸/图上文字 | 违反体系 |
| MJ 正文出现 no/without/avoid | 否定词只进 `--no` |
| 视频条出现「高级/电影感/唯美/epic」 | 抽象夸赞词禁用,写具体物理现象 |
| 一镜到底出现剪辑语 | 剪辑语只属于六镜头分镜 |
| 解卦给出医疗/投资断言 | 越界,改为意象与观照 |
