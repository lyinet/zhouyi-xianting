# 周易仙庭图集 — 设计文档

- 日期：2026-08-09
- 状态：待评审
- 关联：`~/.claude/skills/cinematic-image-prompt/`（底层提示词工程 skill）

## 1. 目标

把《周易》六十四卦各转化为一张唯美中式仙庭风格的 AI 生成图，形成一部有整体感的连载作品，用于小红书 / 公众号发布。

交付两样东西：

1. **提示词库** — 64 卦 × 4 个模型 = 256 条成品提示词
2. **转译 skill** — 把"八境 + 三旋钮"的规则固化下来，使后续改画幅、扩到爻图、换模型时可以重跑而非重写

## 3. 视觉体系

### 3.1 八境

八经卦各对应仙庭中的一处建筑或地貌。

| 经卦 | 象 / 性 | 境 | 视觉要素 | 签名色 |
|---|---|---|---|---|
| ☰ 乾 | 天 / 健 | 天阙 | 云海之上的白玉高台、九重丹陛、无梁金顶、罡风 | 鎏金 + 云白 |
| ☷ 坤 | 地 / 顺 | 地宫 | 夯土层台、梯田式庭院、藏于山腹的暗殿、陶砖 | 赭黄 + 夯土褐 |
| ☳ 震 | 雷 / 动 | 雷坛 | 露天圆坛、青铜编钟与铜柱、焦木、低压雷云 | 青铜绿 + 焦黑 |
| ☴ 巽 | 风 / 入 | 风廊 | 极长空廊、万千经幡纱帘、镂空花窗、竹林 | 竹青 + 纱白 |
| ☵ 坎 | 水 / 陷 | 水府 | 下沉水院、深潭、暗渠水帘、湿滑苔石 | 墨青 + 苔绿 |
| ☲ 离 | 火 / 丽 | 火殿 | 长明灯阵、琉璃铜镜、朱漆廊柱、天光透窗 | 朱红 + 鎏金 |
| ☶ 艮 | 山 / 止 | 山门 | 巨石门阙、绝壁栈道、石阶尽头、苍松界碑 | 苍灰 + 松绿 |
| ☱ 兑 | 泽 / 悦 | 泽苑 | 荷池曲桥、水榭、临水回廊、莲与鱼 | 荷粉 + 水绿 |

八境共处同一座仙庭山水之中，彼此可见、气候连续，不是八个平行世界。

### 3.2 叠合规则（本设计的支点）

**上卦占画面上方，下卦占画面下方。** 这是主轴，64 张一律遵守。

"远/近"与"高/低"是辅助手段，用来加强上下关系，不能替代它：上境通常同时更远更高，下境通常同时更近更低。当卦义要求时可以只用上下而不拉开远近（如八纯卦的层层叠加）。

这条规则使画面结构直接等于卦的结构，而不是给卦义配插图。它自动产生了周易最核心的"交与不交"的视觉表达：

- **泰 ䷊**（坤上乾下）→ 地宫的夯土庭院悬在天上，天阙的云海白玉台反在下方。天地倒置而相交。
- **否 ䷋**（乾上坤下）→ 天阙高悬遥不可及，地宫沉于底部，中间被一层死云彻底隔断。天地不交。
- **八纯卦**（乾、坤、震、巽、坎、离、艮、兑）→ 单境双重叠加，推到极致：天阙九重层层向上，地宫层层向下。

### 3.3 三旋钮

每卦的卦德决定这三个值。推导规则如下，实现时需为全部 64 卦显式赋值并在数据中记录理由。

**光时**（由卦的"时"决定）

| 取值 | 适用 | 例 |
|---|---|---|
| 拂晓 | 初生、始交、蒙昧 | 屯、蒙 |
| 正午 | 盛大、亨通、丰盈 | 乾、大有、丰、泰 |
| 薄暮 | 极盛转衰、剥落、否闭 | 否、剥、遁、姤 |
| 夜 | 晦暗、陷险、终止 | 坎、明夷、困、蹇 |

**天候**（由卦德的顺逆决定）

| 取值 | 适用 | 例 |
|---|---|---|
| 晴 / 薄雾 | 顺、悦、丽 | 泰、大有、兑、离、谦 |
| 雨 / 雪 / 罡风 | 险、阻、难 | 坎、蹇、屯、大过 |
| 浓雾 | 蒙、昧、疑 | 蒙、睽、未济 |

**水势地势**（由卦的动向决定）

| 取值 | 适用 | 例 |
|---|---|---|
| 静（镜面） | 止、待 | 艮、需、大畜 |
| 上涨（漫过石阶） | 进、升、临 | 升、临、晋、渐 |
| 奔涌（激流） | 险、涣、动 | 坎、涣、震、解 |
| 干涸（见底） | 穷、困、竭 | 困、井、剥 |

### 3.4 灵禽

默认丹顶鹤，永远是远景小点，不露脸。它承担两个功能：给建筑以尺度参照，给构图以视觉焦点。参考图中丹顶鹤正是此作用。

数量与状态随卦变：一只为孤（蹇、困），成对为合（咸、恒），群起为涣（涣、萃）。必要时换成玄鸟、白鹿、锦鲤或一叶孤舟。

**不画近景人物、不画人脸。** 这既是美学选择（保持山水意境），也规避了 AI 出图中最不可控的失败模式，且免除 64 张图维持人物一致性的负担。

### 3.5 色板生成规则

不手挑颜色，按规则生成：

```
色板 = 上境签名色（主一） + 下境签名色（主二） + 光时点缀色
```

光时点缀色：拂晓 = 淡金，正午 = 白炽，薄暮 = 橙红，夜 = 月银。

结果落进 `cinematic-image-prompt` skill 的"两主一辅"规则，两个 skill 直接咬合。三个以上主色会让模型调出浑浊的灰。

### 3.6 全局锚点（64 张必须一致）

| 项 | 取值 |
|---|---|
| 画幅 | 3:4 竖版 |
| 渲染语言 | 照相写实 CG 电影剧照，大气透视，微观细节，轻微胶片颗粒 |
| 构图法 | 暗前景框 + 上下二分（上卦/下卦） + 远景消隐 |
| 机位 | 24mm 广角低机位仰视，极远景；下卦为坎或兑时改用平视贴水面以取倒影。不使用俯视——俯视会强调画面下方，与"上卦占上方"的叠合规则相抵消 |
| 明度 | 雾气本身被光点亮，是画面最亮的区域；整体明亮通透，暗部开放保留细节，不压死黑 |
| 尺度 | 建筑体量极大，上境向画面顶部之外继续升高；灵禽小如尘点仅作尺度对照；纵深不少于四层 |
| 灵禽 | 远景小点，不露脸 |
| 排字区 | 顶部约 1/5 留白，供后期排卦名与卦辞 |

**明度与尺度两条锚点是首轮出图后补的。** 初版把「暗前景框」「唯一光源」「nothing else is lit」三条叠加，把环境光与反弹光一并掐死，出图偏暗；同时缺焦段与尺度对照，画面工整但不宏大。参考图其实很亮——雾是发光的，是画面最亮区，暗前景只占很小一块。初版只继承了"暗"，漏了"雾发光"。两条锚点已纳入 `validate.py`，缺任一条即判失败。

**图上不渲染文字。** 中文书法的 AI 渲染在 64 张规模上不可靠，卦名与卦辞一律后期排版。构图预留留白即可。

## 4. 数据模型

### 4.1 `data/realms.json`

八境定义。字段：`trigram`（经卦名）、`symbol`、`element`、`nature`、`realm`（境名）、`elements_zh` / `elements_en`（视觉要素，中英各一份）、`palette`（签名色，中英）。

英文译名需固定下来并全库复用，否则 64 张图的英文提示词里"天阙"会出现十几种译法，成套感在英文模型上就断了。

### 4.2 `data/hexagrams.json`

64 条记录，按序卦顺序（1–64）排列。单一事实来源。

```json
{
  "no": 3,
  "name": "屯",
  "pinyin": "zhun",
  "symbol": "䷂",
  "upper": "坎",
  "lower": "震",
  "guaci": "元亨利貞。勿用有攸往，利建侯。",
  "theme": "萬物初生之難",
  "dials": {
    "light": "拂晓",
    "light_reason": "初生之卦，取一日之始",
    "weather": "暴雨初歇，浓云未散",
    "weather_reason": "屯为险难，坎水在上",
    "terrain": "浑浊上涨",
    "terrain_reason": "水漫坛基，动而遇险"
  },
  "creature": { "kind": "丹顶鹤", "count": 1, "state": "静立乱石不动" },
  "composition": "水府深潭悬于上方，雷坛焦黑的青铜圆坛陷在下方乱石间",
  "palette": ["墨青", "青铜绿", "淡金"]
}
```

`*_reason` 字段是给人审阅用的：没有理由的旋钮值就是随手填的，必须能被辩护。

### 4.3 卦辞来源要求

**卦辞必须从可核实的文本源录入，不得凭模型记忆生成。** 这是硬性要求——AI 复述古籍原文时出错率不低，而错的卦辞会直接印在成品上。

**已确定底本：**[中国哲学书电子化计划 ctext.org](https://ctext.org/book-of-changes/zh)，每卦在 `hexagrams.json` 中记录 `source` URL 可供抽查。除卦辞外一并录入彖传与大象传——大象传给出了权威的一句话卦象陈述（如屯「雲，雷，屯」），是三旋钮取值的依据来源。

原定的维基百科未采用：`zh.wikipedia.org` 在开发所处网络不可达（同网络下 example.com 返回 200）。ctext 作为原文数据库亦优于百科条目。

### 4.4 上下卦分解的验证要求

整套视觉体系依赖 64 卦上下卦分解正确，**不接受凭记忆填写**。分解表须通过四条独立验证，任一不过即为回归：

1. 八经卦各作上卦恰 8 次、作下卦恰 8 次
2. 64 卦画互异且穷尽 2⁶
3. 32 对序卦全部满足反卦（上下颠倒）或错卦（阴阳全变）关系
4. 大象传物象与上下卦相符 64/64

第 3 条约束极紧，几乎任何单点错误都会被抓出；第 4 条取自经文本身，与前三条完全独立。四条已于实现时全部通过。

## 5. skill 设计

`skills/zhouyi-xianting/SKILL.md`

**职责**：输入卦名或卦序，输出该卦的四条提示词。规则来自 `references/`，卦的具体取值来自 `data/hexagrams.json`。

**与 `cinematic-image-prompt` 的关系**：本 skill 是它的特化层。八境组合 + 三旋钮负责填满通用 skill 的 8 槽蓝图，通用 skill 负责翻译成四种模型方言。不重复实现方言层。

槽位映射：

| 通用 skill 的槽 | 本 skill 的来源 |
|---|---|
| 1 画幅/机位 | 全局锚点：3:4 竖版 + 机位规则 |
| 2 主体 | 上下境组合中占主导的那一境 |
| 3 环境 | 两境的视觉要素 |
| 4 三层纵深 | 暗前景框 + 上卦（上/远） / 下卦（下/近） |
| 5 光 | 光时旋钮 |
| 6 氛围 | 天候 + 水势地势旋钮 |
| 7 色板 | 色板生成规则 |
| 8 质感 | 全局锚点：照相写实电影剧照 |

## 6. 实施批次

按**上卦**分 8 批，每批 8 卦。同批共享同一个上境，建筑渲染描述批内复用，一致性与效率同时拿到。

**生产顺序 ≠ 发布顺序**：生产按上卦分组，发布按序卦 1–64。

第 1 批（上卦为乾）：乾、履、同人、无妄、姤、讼、遁、否。

**实现状态：8 批已全部生成**（256 条提示词，`scripts/validate.py` 0 项不通过）。原计划的"先交第 1 批再推其余"未执行，因用户要求一次捋顺全部。出图验证仍按批进行，见第 7 节。

**实现期新增的设计决策：Midjourney 条不使用「天阙」这类自造专名。** 图像模型不认识这些词，写进去只白占词数并稀释主体；专名对系列一致性的作用由 GPT-Image-2 与 Nano Banana Pro 两条承担，MJ 改用 `realms.json` 的 `short_en` 紧凑描述。此项使 MJ 正文从 97–128 词收敛到 81–109 词（均值 93）。

## 7. 验收标准

以下各项已由 `scripts/validate.py` 实现为可执行检查，每次重跑生成器后必须通过（当前 256 条全过）：

- [x] 四条提示词同源：色板成分、画幅在四条中一致
- [x] 上下境叠合方向正确，上境译名出现在英文两条中
- [x] 三旋钮取值在 `hexagrams.json` 中有 `*_reason`
- [x] 色板由规则生成，两主一辅
- [x] 无禁用词（masterpiece / 8k / best quality / ultra detailed / trending on artstation 等）
- [x] Midjourney 带 `--ar 3:4` 与 `--style raw`，否定词只出现在 `--no`（正文出现 no / without / avoid 即判失败）
- [x] 构图预留顶部排字区
- [x] 画面禁令齐备：无近景人物、无人脸、无渲染文字
- [x] 中文提示词不混入英文单词
- [x] 无拼接残留与重复短语（英文三元词组重复即判失败）

**机械验收不能替代人眼。** 语法通顺、主谓一致、语义是否自相矛盾，验证器查不出——首轮实现中「stacked cloud terraces loses itself」「两个 end of the」这类问题均是人眼发现后才补进检查项的。每批仍需通读。

出图验证由用户执行：每批抽验 2–3 卦，四个模型各出一张，确认成套感成立。

## 8. 明确不做的

- 384 爻图（本期范围外，但数据模型保留扩展余地）
- 十翼篇章配图
- 每期发布文案（用户已选择不含）
- 图上文字渲染（一律后期排版）
- 近景人物与人脸

## 9. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 卦辞记忆出错 | 成品印错古籍原文 | 强制从可核实底本录入，见 4.3 |
| 八境英文译名漂移 | 英文模型上成套感断裂 | 译名在 `realms.json` 固定，全库复用 |
| 相邻卦画面雷同 | 连载观感重复 | 同上卦的 8 卦靠三旋钮拉开差异，批内交付时横向比对 |
| 旋钮取值流于随意 | 卦义与画面脱节 | `*_reason` 字段强制可辩护 |
| MJ `--v 8.2` 版本号不被账号接受 | 提示词报错 | 报错时去掉该参数，见 `cinematic-image-prompt` 的 model-dialects.md |
