## 1. 动机

**灵禽**：用户指出所有出图里都有丹顶鹤，不喜欢这个设定。查数据确认 63/64 用丹顶鹤（仅坤卦白鹿）——种类从一开始就被我固定成默认值，只有数量与状态随卦变，所以 64 张看下来是同一只鹤。

更实质的问题是**功能重复**：上一轮为解决"不够宏大"加入了「三个极小袍服人影」作尺度锤子后，鹤的尺度功能已被取代。画面里有两套装置在做同一件事，而鹤是其中更套路的那个。

**抖音文案**：项目产出止于提示词，发布环节仍需手写标题、简介、标签，是断的。

## 3. 远景人物设计

### 3.1 唯一性

**画面里只有这一处人物。** 旧的「固定三人影」与「灵禽」两套装置合并为一。两套并存会争夺视觉焦点，也让尺度参照失去基准。

### 3.2 字段

`hexagrams.json` 的 `creature` 整体替换为 `figure`：

```json
"figure": { "count": 2, "pose": "分立阶侧如守", "robe_zh": "白炽", "robe_en": "white-hot" }
```

- `count` ∈ {1, 2, 3}，承接原灵禽的卦义编码：**1 孤 / 2 合 / 3 群**。原表的 5/7/9/12 一律归 3——远景背影上再多的人数分辨不出，保留大数只会让模型堆人。
- `pose` 逐卦重写，不从鹤的状态机械转换。照抄会产出「一位女子四散飞开」这类东西。
- `robe_zh` / `robe_en` **不手挑**，自动取该卦色板的第三色（光时点缀色）。这是人物与画面同源的唯一保障，`validate.py` 强制。

### 3.3 描述限度

只写**衣制、姿态、朝向**。不写容貌、年龄、五官——一旦写了，模型会把人物拉到中景并试图渲染脸，破坏"远景小点"的定位。`validate.py` 扫 `pose` 字段的容貌/年龄词，命中即失败。

### 3.4 一致性策略

不要求 64 张同一人，只锁气质与服制。这避免了角色一致性工作流（参考图 + 每张重跑），使每卦仍可独立出图。

## 4. 抖音发布文案

### 4.1 平台事实

抖音发布界面只有一个「作品描述」框，话题用 `#` 写在描述里，没有独立的标题/简介字段。故产出按**实际粘贴顺序**给在一个代码块内：标题行 → 空行 → 简介 → 空行 → 话题。

### 4.2 结构

| 段 | 约束 | 来源 |
|---|---|---|
| 标题行 | ≤20 字（抖音首行约 20 字后折行） | `douyin.json` 的 `title_patterns`，四式按 `use_when` 择一 |
| 简介 | 三句、总长 ≤120 字：画面 / 卦义观照 / 开放式引导 | 八境 + 三旋钮 + 卦辞大象 |
| 话题 | 恰好 6 个 = 泛流量 3 + 垂类 2 + 系列专属 1 | `douyin.json` 的 `tags` |
| 封面排字 | 另给一行建议，不在生图时渲染 | `douyin.json` 的 `cover_text` |

泛流量标签**逐期轮换**，不每期全同；系列专属 `#周易仙庭` 固定——标签一漂，系列在推荐算法侧就散了。

### 4.3 红线

`douyin.json` 的 `banned` 分三类：诱导互动、封建迷信与绝对化、吉凶断言。一个都不许出现。不给医疗/投资/法律断言——与解卦段同一原则。

`validate.py` 额外检查 `douyin.json` 自带的示例文案是否踩了自己的禁用词。

## 7. 已知取舍

- **人数压到 1/2/3**：损失了原灵禽 5/7/9/12 的粒度。远景背影上这个粒度本来就分辨不出，且大数会让模型堆人。
- **不要求同一人**：连载的人物辨识度弱于固定角色，换来的是每卦可独立出图、无参考图依赖。
- **抖音文案走国风美学向**：放弃了占卜话题天然的传播性，换取内容合规风险更低、受众更宽。
